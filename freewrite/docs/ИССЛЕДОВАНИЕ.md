## 1. Какой Android API доступен на HarmonyOS 4.3

- HarmonyOS версий 2–4 построена на открытом коде Android (AOSP) и запускает обычные APK.
  Ваш планшет это уже подтверждает: на нём работают Microsoft Word и WPS Office из APK.
- HarmonyOS 4.x обычно сообщает приложениям **Android 12 (API 31)**. Точное число
  приложение покажет в строке «Android API».
- Не путать с **HarmonyOS NEXT / 5** (китайские прошивки): там APK не запускаются вообще.
  Международная MatePad Mini с HarmonyOS 4.3 — не этот случай.
- ML Kit Digital Ink 19.0.0 требует Android 6 (API 23) или новее (документация Google).
  Проект собирается так: `minSdk 26` (Android 8 — с запасом), `targetSdk 34`, `compileSdk 35`.

## 2. Можно ли использовать Kotlin и стандартные API Android для пера

Да. Kotlin компилируется в обычный байткод Android, HarmonyOS 4 его исполняет.
Для пера используются стандартные события `MotionEvent`:

- `getToolType()` → `TOOL_TYPE_STYLUS` отличает перо от пальца (`TOOL_TYPE_FINGER`);
- `getHistoricalX/Y()` — промежуточные точки между кадрами экрана, чтобы штрих был плавным;
- `getEventTime()` — время каждой точки (ML Kit учитывает порядок и скорость штрихов);
- `getPressure()` — нажим; `getAxisValue(AXIS_TILT)` — наклон пера;
- `requestUnbufferedDispatch()` — точки приходят сразу, без группировки по кадрам, меньше задержка.

Фирменные функции Huawei (двойное касание и сжатие M-Pencil Pro, отклик вибрацией,
системный FreeScript) идут через закрытые сервисы Huawei. Сторонним APK они **не нужны и не
используются**: приложение опирается только на стандартный Android.

## 3. Работает ли Google ML Kit Digital Ink без сервисов Google

**Короткий ответ:** по устройству библиотеки — должно. Google это явно не гарантирует,
поэтому решает проверка на планшете.

**Почему должно работать.** У ML Kit три способа поставки моделей ([Google: ML Kit model installation paths](https://developers.google.com/ml-kit/tips/installation-paths)):

1. **«unbundled»** — модель живёт внутри Google Play Services. Без сервисов Google не работает.
2. **«bundled»** — модель встроена в APK.
3. **«dynamically downloaded»** — модель скачивается самой библиотекой ML Kit.

Google прямо относит Digital Ink Recognition к третьему типу: «Dynamically downloaded models
are offered for APIs with extensive model options, such as Digital Ink Recognition and
Translation», а «Unbundled: Models are downloaded and managed via Google Play Services» — это
другой путь. Сама библиотека и её модуль задач (`play-services-tasks`) — обычный код внутри
нашего APK, а не установленное приложение Google.

**Что видно внутри собранного APK** (разбор манифеста, 07.11.2026):

- модели скачиваются через стандартный планировщик Android `androidx.work` (WorkManager) —
  своим загрузчиком ML Kit, без сервисов Google;
- есть заготовки клиентской библиотеки сервисов Google (`GoogleApiActivity`,
  `com.google.android.gms.version`). Они срабатывают, только если вызвать API сервисов Google,
  а распознавание их не вызывает;
- есть модуль статистики Google (`datatransport`). Без сервисов Google он должен просто не
  отправлять данные.

**Риски:**

- Явной фразы «работает без Google Play Services» в документации нет.
- Сервер загрузки моделей Google может быть недоступен в какой-то сети. Тогда помогает
  другая сеть или VPN на время загрузки: модель качается один раз.
- Внутренние вызовы ML Kit к сервисам Google (статистика) на устройстве без них должны
  тихо пропускаться. Если вместо этого приложение упадёт, текст ошибки сохранится
  и попадёт в отчёт при следующем запуске.

**Как проверяет приложение:** раздел «1. Модель распознавания» → «Скачать». Результат,
время загрузки и полный текст ошибки (класс, код ML Kit, причина) попадают в отчёт.

## 4. Можно ли скачать и установить русскую модель

- Код языка — `ru`, размер — около 20 МБ ([Google: Digital Ink на Android](https://developers.google.com/ml-kit/vision/digital-ink-recognition/android)).
- В официальном списке языков: «Russian, Cyrillic script — `ru`, `ru-x-gesture`». Вариант
  `ru-x-gesture` дополнительно понимает жесты (например, зачёркивание) — пригодится для
  исправлений на следующих этапах ([список моделей](https://developers.google.com/ml-kit/vision/digital-ink-recognition/base-models)).
- Google: распознавание «works fully offline (aside from a one-time download of language
  packs)» и это «the same technology that powers handwriting recognition layouts in Gboard».
- Проект использует `com.google.mlkit:digital-ink-recognition:19.0.0` (выпуск 29.08.2025:
  поддержка 16 КБ страниц памяти на новых устройствах). Улучшение моделей для кириллицы было
  в выпуске 2020 года ([ML Kit release notes](https://developers.google.com/ml-kit/release-notes)).
  В первой версии этого документа ошибочно было написано «в январе 2026» — исправлено после
  сверки с официальной страницей.
- Модель скачивается один раз. Потом распознавание идёт целиком на планшете, без интернета.
  Тест 6 инструкции (режим полёта) это проверяет.
- Английский — `en-US`, скачивается отдельно той же кнопкой.

## 5. Какие есть другие локальные движки, если ML Kit не заработает

| Вариант | Офлайн | Русский | Качество | Минусы |
|---|---|---|---|---|
| **MyScript iink SDK** | да | да, в их приложениях Nebo/MyScript Notes | лучшее на рынке, сопоставимо с Samsung | платный, цена по запросу; лицензия активируется через интернет; компания французская — продажа в Россию может быть ограничена |
| Своя нейросеть (LSTM/Transformer по штрихам, TensorFlow Lite / ONNX) | да | нужно обучать самим | заметно ниже ML Kit без больших данных | месяцы работы, нужны тысячи образцов почерка |
| Huawei HMS ML Kit | — | — | — | по нашим данным, распознавания штрихов (а не фото) для APK там нет; Huawei Pen Kit есть только в HarmonyOS NEXT |
| Картинка штрихов + OCR рукописи (Tesseract, TrOCR) | да | частично | хуже для связного почерка | теряются порядок и время штрихов. ТЗ запрещает без отдельного обоснования — **отклонено** |
| Облачные API (Google Cloud Vision, Yandex Vision OCR) | нет | да | хорошее | нужен интернет, это OCR картинки, платно — **отклонено для MVP** |

**Вывод:** основной путь — ML Kit. Запасной — MyScript iink. Распознавание спрятано за одним
классом `HandwritingEngine`, поэтому движок можно заменить, не переписывая приложение.

## 6. Как организовать последовательное распознавание без дублирования

Главная идея: текст в документе и текущая рукопись **никогда не смешиваются**, пока слово
не зафиксировано. Три слоя:

1. **Документ** — уже зафиксированный печатный текст. Меняется только командой «зафиксировать»
   или правкой пользователя.
2. **Черновая группа** — штрихи, которые ещё не превратились в текст. У группы есть номер.
3. **Промежуточный результат** — варианты распознавания черновой группы. Показывается серым у
   курсора и **заменяется** при каждом новом ответе. Никогда не дописывается.

**Цикл работы:**

1. Перо оторвалось → через ~0,3 с распознаём **всю** черновую группу целиком, с номером запроса.
2. Пришёл ответ. Если его номер не последний (пока ждали, пользователь дописал штрих), ответ
   выбрасываем. Иначе обновляем промежуточный результат.
3. **Фиксация группы** — по одному из условий:
   - пауза после последнего штриха (настраиваемая, по умолчанию ~1,5–2 с: длиннее обычной
     паузы между буквами);
   - новый штрих начат далеко от черновой группы (другое место экрана) — так работает
     «пишу в любом месте»: старая группа фиксируется сразу, новый штрих начинает новую группу;
   - кнопка/жест «готово» или группа стала слишком большой (строка целиком).
4. При фиксации лучший вариант (или выбранный пользователем) вставляется в документ у курсора.
   Пробел ставится по правилам (не перед знаками препинания). Номер группы помечается как
   зафиксированный, её штрихи плавно исчезают.
5. Ответ, пришедший позже для уже зафиксированной группы, игнорируется по номеру. **Отсюда
   нет дублей:** каждая группа попадает в текст ровно один раз.

**Дополнительно:**

- В распознаватель передаём до 20 символов текста перед курсором (`preContext`). ML Kit точнее
  угадывает слово и сам решает, нужен ли пробел: по документации после «hello» он вернёт
  « world» — с пробелом в начале. Приложение этот пробел учитывает и второй не добавляет.
- **Высота строки.** Google: распознаватель считает, что в области письма одна строка, и по
  размеру букв относительно неё отличает «о» от «О» и запятую от косой черты. Если поле
  вмещает несколько строк, лучше передавать высоту **одной строки**. С версии 0.1.2 приложение
  передаёт оценку высоты строки: медиану высот уже добавленных слов, а для первого слова —
  высоту самой надписи.
- Отмена: каждая фиксация — один шаг отмены («убрать вставленное слово»).
- Исправление: варианты распознавания хранятся вместе со словом, нажатие на слово
  показывает альтернативы.

**Что уже есть в этапе 1:** номер запроса и отбрасывание устаревших ответов, распознавание всей
группы после паузы, `preContext`, вставка у курсора с пробелами, кнопка «✓ В текст» и
нажатие на вариант. Автоматическая фиксация по паузе и по месту — задача этапа 2.

## 7. Ограничения HarmonyOS при работе с Canvas и пером

Что известно заранее, а что проверит отчёт:

- **Рисование.** Обычный `View` + `Canvas` с аппаратным ускорением работает как в Android:
  HarmonyOS 4 использует тот же графический стек. Специальный режим сверхнизкой задержки
  (`androidx.graphics.lowlatency`, рисование в передний буфер) на HarmonyOS может не работать,
  поэтому пока не используется. Вместо него — `requestUnbufferedDispatch` и промежуточные точки.
- **Тип инструмента.** Ожидаем, что M-Pencil приходит как `TOOL_TYPE_STYLUS`. Если система
  отдаёт его как палец, в приложении есть переключатель «Писать и пальцем», а отчёт это покажет.
- **Нажим.** Перо аппаратно различает 4096 уровней. Сколько из них доходит до приложения, видно
  в строке «Нажим: меняется (…, уровней: N)».
- **Наклон и наведение.** Фирменные приложения Huawei их используют. Доходят ли они до
  стороннего APK, неизвестно: отчёт покажет «наклон: передаётся / не передаётся»
  и «наведение пера: да / нет».
- **Ладонь.** Касания пальцем и ладонью не рисуют. Если ладонь легла раньше пера, её след
  выбрасывается, как только касается перо.
- **FreeScript.** Поле для письма — обычный `View`, а не текстовое поле, поэтому системный
  рукописный ввод не должен вмешиваться. Если при письме в поле появляется панель FreeScript,
  это нужно отметить.
- **Установка APK.** В HarmonyOS есть «Чистый режим», он блокирует установку не из AppGallery.
  Как его обойти для одной установки — в инструкции.

## Выбранная архитектура

- **Нативное Android-приложение на Kotlin.** Даёт прямой доступ к `MotionEvent` и минимальную
  задержку.
- **Поле для письма — собственный `View`.** Остальной интерфейс на этапе 1 — стандартные
  элементы Android без лишних библиотек: меньше риск несовместимости с HarmonyOS и меньше APK.
  На этапах 2–4 интерфейс можно перевести на Jetpack Compose, а поле для письма останется
  своим `View` и встроится через `AndroidView`.
- **Распознавание — ML Kit Digital Ink**, за интерфейсом `HandwritingEngine` (можно заменить
  на MyScript).
- **Хранение (этап 4):** Room — документы, DataStore — настройки.
- **Сборка — GitHub Actions.** Каждое изменение собирает APK. Он лежит по постоянной ссылке
  в выпуске `freewrite-latest`. Android Studio для работы не обязательна. С 07.11.2026 APK
  можно собрать и в облачной среде Claude (там установлен Android SDK) — для быстрых проверок.

## Сверка с документацией и что выяснилось при сборке

- Первая версия документа писалась без доступа к developers.google.com. После открытия доступа
  (07.11.2026) факты сверены с официальными страницами; ошибка про «январь 2026» исправлена.
- Имена классов ML Kit сверены прямо с библиотекой при сборке. В 19.0.0 Google переложил классы
  в новые пакеты (в примечаниях к выпуску об этом не сказано):
  - `com.google.mlkit.vision.digitalink.recognition` — распознаватель, модель, контекст и `Ink`
    со вложенными `Ink.Stroke` и `Ink.Point`;
  - `com.google.mlkit.vision.digitalink.common` — общие классы (результаты распознавания и др.),
    отдельный модуль `digital-ink-common 16.0.0`.

  Старые примеры в интернете с пакетом `com.google.mlkit.vision.digitalink` к этой версии не
  подходят.
- Поведение на конкретном планшете (API, перо, загрузка модели) можно узнать только из отчёта
  приложения.
